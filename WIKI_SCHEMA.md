# Wiki Store Schema

This is the v1 on-disk contract for the persistent wiki. The store implementation and `/wiki-dream` must follow it.

## Location

For a project whose existing knowledge directory is:

```text
<agent-dir>/pi-wiki-skills/projects/<sanitized-project-id>/
```

its wiki lives at:

```text
wiki/
├── patterns/
│   └── <pattern-id>.md
├── evolution.md
└── skill-impact.md
```

`<pattern-id>` is a UUID generated by the store. It is never derived from a title or user input.

## Pattern Pages

Each page is one reusable success or failure pattern. It begins with YAML front matter followed by Markdown body sections.

```md
---
id: "018f..."
kind: "success" # "success" | "failure"
status: "active" # "active" | "superseded"
title: "Verify an anchor before using it as evidence"
createdAt: "2026-08-30T00:00:00.000Z"
updatedAt: "2026-08-30T00:00:00.000Z"
sources:
  - sessionId: "01a..."
    entryIds: ["a1b2c3d4", "e5f6a7b8"]
---

## Observation

What repeatedly happened.

## Evidence

Why the cited entries support the observation.

## Guidance

Actionable instruction for a future agent.

## Limits

When this pattern does not apply.
```

`sessionId` and `entryIds` reference source anchors in `source-anchors.jsonl`; the resolver supplies the session file and hash verification. Pages never embed raw Pi session content solely for archival purposes.

## Evolution Log

`evolution.md` starts with `# Wiki Evolution Log`. Every maintainer change appends one entry; existing entries are never edited.

```md
## 2026-08-30T00:00:00.000Z — create-pattern

- Pattern: `018f...`
- Sources: `session-id/entry-id`, `session-id/entry-id`
- Change: Created the pattern page.
- Rationale: Concise explanation tied to the cited evidence.
```

Allowed operations are `create-pattern`, `update-pattern`, and `supersede-pattern`.

## Skill-Impact Log

`skill-impact.md` starts with `# Skill Impact Log`. It remains empty until versioned skill proposals exist. Each future proposal and its validation outcome appends one entry:

```md
## 2026-08-30T00:00:00.000Z — proposal <proposal-id>

- Based on patterns: `018f...`
- Candidate skill version: `<version>`
- Validation: pending | accepted | rejected
- Score: `<score or n/a>`
- Rollback target: `<last accepted version or n/a>`
```

## Invariants

- Pattern IDs, log timestamps, and source references are machine-readable and stable.
- Pattern pages may be revised only through a logged wiki operation.
- Both logs are append-only.
- Missing or unverifiable source anchors must not be used to create or update a pattern.
